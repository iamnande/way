# Tech Spec — way craft pillar: Craft + session log

## Overview + Design Principles

Adds `Craft` and `CraftSession` as new first-class entities, following the
same principles as `Routine`/`RoutineCompletion`: additive, `Store` is the
only architectural boundary, redb JSON-blob persistence (app data, not
config — no bearing from [issue #20](https://github.com/iamnande/way/issues/20)),
CLI-first, no TUI in this MVP (provisional pending
[issue #21](https://github.com/iamnande/way/issues/21), same as every prior
pillar).

`CraftSession` deliberately mirrors `RoutineCompletion`'s shape almost
exactly — same "dated log entry, optional note, references its parent by
name, no uniqueness constraint on (parent, date)" pattern. No new design
here, just applying an already-solved shape to a second entity.

`Store` gains a fifth trait, `CraftStore`, joining `TaskStore`/
`ProfileStore`/`RoutineStore`/`PersonStore` under the existing `Store`
supertrait.

## Data Model

```rust
// craft.rs (new file)
#[derive(Debug, Clone, Copy, PartialEq, Serialize, Deserialize)]
pub enum CraftStatus {
    Active,
    Dormant,     // not currently practiced, contingent on something outside nick's control (e.g. military/IRR)
    Historical,  // genuinely past, no realistic path back
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Craft {
    pub id: u64,
    pub name: String,          // unique - primary key, same as Routine
    pub status: CraftStatus,
    pub space: String,         // freeform: your niche/focus within this discipline
    pub standing: String,      // freeform: where you stand relative to whatever's relevant (market, community, self)
    pub trajectory: String,    // freeform: direction of growth + why, combined
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CraftSession {
    pub id: u64,               // nanosecond timestamp, same id scheme as Task::id / RoutineCompletion::id
    pub craft_name: String,    // loose reference by name, same style as RoutineCompletion.routine_name
    pub logged_on: i64,        // unix seconds, may be backdated via --date - deliberately not "practiced_on": not every craft session is "practice" (woodworking is building something, not drilling a rep)
    pub note: Option<String>,
}
```

`Craft` is name-keyed (unique), same rationale as `Routine`: these are a
small, deliberately curated set nick maintains explicitly, not a growing
log — unlike `Person`, where duplicate names are plausible and expected.

### Redb tables

```rust
const CRAFTS_TABLE: TableDefinition<&str, &[u8]> = TableDefinition::new("crafts");
const CRAFT_SESSIONS_TABLE: TableDefinition<u64, &[u8]> = TableDefinition::new("craft_sessions");
```

`RedbStore::open` gains both table opens alongside the existing ones.
`add_craft` rejects a duplicate name, matching `add_routine`.

## Store Trait

```rust
pub trait CraftStore {
    fn add_craft(&self, name: String, status: CraftStatus) -> Result<Craft>;
    fn list_crafts(&self, status: Option<CraftStatus>) -> Result<Vec<Craft>>;
    fn find_craft(&self, name: &str) -> Result<Option<Craft>>;
    fn remove_craft(&self, name: &str) -> Result<()>;
    fn set_craft_status(&self, name: &str, status: CraftStatus) -> Result<()>;
    fn set_craft_space(&self, name: &str, space: String) -> Result<()>;
    fn set_craft_standing(&self, name: &str, standing: String) -> Result<()>;
    fn set_craft_trajectory(&self, name: &str, trajectory: String) -> Result<()>;
    fn log_craft_session(&self, craft: &str, logged_on: i64, note: Option<String>) -> Result<CraftSession>;
    fn craft_session_history(&self, craft: &str) -> Result<Vec<CraftSession>>;
}

pub trait Store: TaskStore + ProfileStore + RoutineStore + PersonStore + CraftStore {}
impl<T: TaskStore + ProfileStore + RoutineStore + PersonStore + CraftStore> Store for T {}
```

Narrow single-field setters, same convention as `Person`'s mutators —
updating `standing` doesn't require re-specifying `space`/`trajectory`.

## Interfaces

```
way craft add <name> --status <active|dormant|historical>
    Creates a craft. Errors if the name already exists.

way craft list [--status <active|dormant|historical>]
    Lists crafts, optionally filtered by status.

way craft show <name>

way craft remove <name>
    Deletes outright - no archive state (status already covers it).

way craft set-status <name> <active|dormant|historical>
way craft set-space <name> "<text>"
way craft set-standing <name> "<text>"
way craft set-trajectory <name> "<text>"

way craft log <name> [--date YYYY-MM-DD] [--note <text>]
    Records a session. --date defaults to today. Never requires
    the craft to be Active.

way craft history <name>
    Lists a craft's sessions, reverse-chronological.
```

All non-interactive (CLI-first). No search verb (see PRD Non-Goals).

## Tests

Mirror existing `store.rs` conventions (directly parallel to
`Routine`/`RoutineCompletion`'s test shape):

- `add_craft` rejects a duplicate name; `find_craft` round-trips all fields.
- `list_crafts(None)` returns all crafts; `list_crafts(Some(status))`
  filters correctly.
- `set_craft_status`/`set_craft_space`/`set_craft_standing`/
  `set_craft_trajectory` each mutate only their own field.
- `remove_craft` deletes outright — `find_craft` returns `None` afterward.
- `log_craft_session` on a `Dormant`/`Historical` craft succeeds; on a
  nonexistent craft name errors.
- `log_craft_session` twice for the same craft/date both persist as
  separate rows (no uniqueness constraint).
- `craft_session_history` returns reverse-chronological order.
- `Store` blanket impl: `CraftStore` joins the existing four-trait
  combination with no additional glue code, existing `Box<dyn Store>` call
  sites unaffected.

## Rollout

Single-commit, purely additive — new entities, new tables, new trait
constituent. No coordination with any other repo, no dependency on
[issue #20](https://github.com/iamnande/way/issues/20) (redb-side app data,
not config).
